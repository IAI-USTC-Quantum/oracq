# pyqecclang 全项目 API 文档（Sphinx）完善计划

## 现状结论（已勘察）

项目**已有**一套 Sphinx API 文档机制：`tools/generate_api_docs.py` 为 `src/pyqecclang/{infrastructure,algorithms,applications}` 每个模块生成 `docs/api/**/*.rst`（automodule 页面），conf.py 已配 napoleon（Google 风格）、furo、zh_CN、viewcode；构建以 `-W --keep-going` 把 warning 当错误。本计划**沿用该机制补全**，不另建体系。

三个缺口：
1. **页面过期**：`infrastructure/estimate.py`、`backends/quantikz.py`、`backends/strict.py` 无 API 页（生成器未重跑，TITLES 表也缺三项）。
2. **顶层门面无总览页**：根包 `pyqecclang/__init__.py` 导出 92 个核心名字（Builder、simulate、QVector/QMatrix 等），是用户最常接触的入口，但 `docs/api/` 没有对应页面。
3. **docstring 覆盖低**：根 `__all__` 92 个名字中 30 个无 docstring（集中在 `operators`、`ir`、`serialization` 等 16 个模块）；全项目未文档化公开成员约 800 个（函数 707、类 104 及方法）。这些成员在 API 页面上只有裸签名。

## 改动内容

### 1. 修复并扩展生成器 `tools/generate_api_docs.py`
- TITLES 增加：`estimate: "资源估计"`、`quantikz: "Quantikz 线路导出"`、`strict: "严格网表导出"`（标题依据各模块 docstring）。
- 新增**顶层包总览页**生成逻辑：导入根包（`sys.path` 注入 `src`，与 conf.py 一致），读取 `pyqecclang.__all__`，按 `__module__` 归组到三层各模块，生成 `docs/api/toplevel.rst`（标题「pyqecclang 包总览」）：每模块一小节，标题用 `:doc:` 链到对应 API 页，名字用 `:obj:` 角色交叉引用（canonical 路径，非 nitpicky 模式下解析失败也不产生 warning）。无 `__module__` 的常量（如 `VERSION`）归入"常量"小节。
- `docs/api/index.rst` 的 toctree 把 `toplevel` 置于三个分组之前（生成器自动重写）。
- 重跑生成器：产出 3 个新模块页 + toplevel 页 + 更新 3 个分组 index。

### 2. 全项目 docstring 补全（用户已确认最大范围）
覆盖三层所有公开成员（模块级 docstring 已 100%，补类、函数、方法、关键 dataclass 字段）。

**风格规范**（与仓库现状及 napoleon 配置一致）：
- 中文、Google 风格（`Args:`/`Returns:`/`Raises:`/`Attributes:`）。
- 复杂可调用写完整段落；简单工厂（`Bits()`/`UInt()`）、异常类、re-export 写一至两句；关键 dataclass 用 `Attributes:` 列字段含义。
- **不写 `>>>` 可执行示例**——autodoc 渲染的 docstring 会被 doctest builder 执行，示例统一留在 manual/tutorials。
- **零行为改动**：不改签名、不改逻辑、不加导入；docstring 是唯一改动。
- **不做**的文件（沿用「旧路径只保留导入兼容，不重复列出」既有策略）：`_compat.py`、两个 `legacy.py`、`_dynamics.py`（私有）、`__main__.py`（CLI 已有 manual/cli.md）、顶层 `qham/` 兼容别名包。
- 每个 docstring 必须先读源码理解真实行为再写，准确性优先于覆盖率。

**分批推进**（每批结束跑一次完整构建，warning 早暴露）：
1. infrastructure 层（11 模块 + backends 5 + mathfunc 5）
2. algorithms 层（48 模块）
3. applications 层（8 模块 + qham 子包 6）

大批次可用子代理并行（按统一风格规范分派），我统一复核与构建验证。

### 3. 配套文档更新
- `docs/development/writing-docs.md` 的「API 页面」一节补充顶层总览页的生成说明。
- 无 IR 语义改动，不触发 rir.md/JSON Schema 同步义务。

## 验证（每批 + 最终）

```bash
uv run python tools/generate_api_docs.py
uv run --extra docs python -m sphinx -W --keep-going -b html docs out/docs/html
uv run --extra docs python -m sphinx -W --keep-going -b doctest docs out/docs/doctest
uv run ruff check src tools
uv run python -m unittest discover -s tests/core -v
```

注意：系统 python 为 3.9（缺 `typing.TypeAlias` 无法导入本包），一切命令必须 `uv run`（`.venv` 已在勘察时创建）。最终以 `tools/check_project.py --docs` 口径（tests/docs + HTML + doctest）作为验收标准。不执行 git commit/push。
