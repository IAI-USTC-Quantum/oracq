# 输入契约与工程整理计划

范围：将 oracle/protocol 的组装边界变为可查询、可预检查、可诊断的公开 API，建立可重复的工程验收。算法数值正确性、收敛与复杂度优势继续独立标记为实验状态；不以生产级语言核心的目标替代这些证明。

| 项目 | 交付 | 状态 |
|---|---|---|
| C1 | 算法库自有 Python 协议、描述快照与报告；不设全局类型枚举 | done |
| C2 | QLSS 与 QODE protocol 提供 contract/check，生成前检查输入与输出 | done |
| C3 | 标注不覆盖能力限制；绑定保留既有 ABI 边界，不新增语言级数学检查 | done |
| C4 | 公开算法配置和输入模型的确定性校验、回归测试 | done |
| C5 | 新手完整例子、接口/迁移/成熟度说明、CI 与安装包验收 | done |

验收：完整 core/schema 测试、真实后端集成测试、lint、源码/wheel 安装、最小契约案例以及既有 ODE 示例均通过。检查不要求外部云服务，也不修改相邻仓库；不使用 mock 或 skip 替代后端证据。RIR 的模块结构与版本保持不变；若增加库级属性约定，同步规范并验证序列化与绑定语义。

用户补充决策已纳入：协议在算法库中逐步扩展，单个对象可以满足多个协议。没有修改 RIR 格式、Schema 或语言验证器。工程结果与未认证范围见 engineering-readiness.md 和 contract-hardening-validation.json。
